## Bối cảnh

Repo sắp chuyển sang private trên gói GitHub Free (ADR-0213, PR #130). Khi đó mỗi tháng chỉ có
**2.000 phút** Actions, và GitHub tính **từng job, làm tròn lên phút** — job chạy 6 giây vẫn tính
1 phút.

Hiện tại `ci.yml` chạy cả 21 job cho **mọi** lần push vào PR và mọi lần push lên `main`. Đo ngày

## Những gì đã biết chắc

- **Tính tiền**: "GitHub rounds the minutes and partial minutes each job uses up to the nearest
  whole minute" — [actions runner pricing](https://docs.github.com/en/billing/reference/actions-runner-pricing).
  Repo public dùng runner chuẩn thì miễn phí; GitHub Free có 2.000 phút cho repo private —
  [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
- **Bộ lọc `paths`**: không dùng chung `paths` với `paths-ignore`; dùng `paths` có `!`. Thứ tự
  quyết định: mẫu `!` đứng sau loại một file ra, mẫu thường đứng sau nữa đưa nó vào lại. Với PR,
  GitHub so sánh kiểu ba chấm (nhánh so với điểm tách khỏi base) — tức là **toàn bộ diff của PR**,
  không phải riêng commit vừa push. Nếu diff quá 3.000 file mà file khớp không nằm trong 3.000 file
  đầu thì workflow không chạy —
  [workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).
- **Bẫy "Pending mãi"**: workflow bị bỏ qua vì `paths` thì các check của nó nằm ở trạng thái
  *Pending*, và nếu check đó là *required* thì PR không merge được; còn job bị bỏ qua vì `if` thì
  báo *Success* —
  [troubleshooting required status checks](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/collaborating-on-repositories-with-code-quality-features/troubleshooting-required-status-checks#handling-skipped-but-required-checks).
- **Hôm nay không có check nào bắt buộc.** `gh api repos/tmthang86/fixbolt/branches/main/protection`
  trả **404**; ruleset 23642557 `main-branch-protect` chỉ có `deletion` và `non_fast_forward`
  (đọc 2026-09-28). Khi repo thành private trên Free thì branch protection và ruleset **không còn
  dùng được** —
  [about protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).
- **Sự kiện `pull_request`**: mặc định chỉ chạy với `opened`, `synchronize`, `reopened`; muốn chạy
  khi gắn nhãn phải khai `labeled`. PR đang xung đột merge thì không chạy workflow nào —
  [events that trigger workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request).
- **Sự kiện do `GITHUB_TOKEN` gây ra không tạo run mới**: "events triggered by the `GITHUB_TOKEN`
  will not create a new workflow run", trừ `workflow_dispatch` và `repository_dispatch` —
  [GITHUB_TOKEN](https://docs.github.com/en/actions/concepts/security/github_token). Gỡ nhãn khỏi PR
  đi qua API của issue: `DELETE /repos/{owner}/{repo}/issues/{issue_number}/labels/{name}` ("Every
  pull request is an issue") — [labels API](https://docs.github.com/en/rest/issues/labels#remove-a-label-from-an-issue).
- **Concurrency**: `cancel-in-progress: true` huỷ run đang chạy trong cùng nhóm khi run mới vào —
  [control concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency).
  Nhóm hiện tại là `${{ github.workflow }}-${{ github.head_ref || github.ref }}` (`ci.yml` dòng
  35–37).
- **Hai file tài liệu bị test code đọc lúc chạy**: `docs/CONFIGURATION.md`
  (`crates/engine/src/settings.rs:2113`, `DOC_PATH`) và `docs/reference/prior-art.md`
  (`crates/session/tests/drop_reason.rs:314`). Cả hai chạy trong `cargo test --all` của `gates`.
  README của crate `fixbolt` là tài liệu của crate (`crates/library/src/lib.rs:1`) nên là doctest —
  nhưng nó nằm trong `crates/`, vốn đã là code.
- **Script trong CI đọc tài liệu**: `stranger-check.sh` dán code từ `docs/GETTING-STARTED.md` (job
  `package` với `--from packaged`, job `stranger-git` với `--from git`); `check-doc-samples.sh`,
  `check-doc-claims.sh`, `check-cited-headings.sh` (job `book`, `links`) đọc `docs/` và các `.md` ở
  gốc.
- **Job nào cần máy riêng — theo chính comment trong `ci.yml`**: `dict-no-vendor` và `package`
  chứng minh build khi *không có* `vendor/`; `no-default-features` chạy "on its own runner, so it
  cannot inherit anything a previous step put there"; `tls`, `interop-qfj`, `no-kernel-sleep`,
  `standard-blocks` kiểm kernel của runner trước và báo lỗi môi trường bằng lời riêng.
  `lint-config` cố ý không tải `vendor/` để `check-dict-spec-pin.sh` đi nhánh chỉ-sha256.
  `script-logic` là logic thuần, "on a runner whose own kernel state is irrelevant". `stranger-git`
  ghi rõ `vendor/` trên runner "has no path into that build at all".
- **Thời gian từng bước** (run 36373978028): `gates` — `cargo test --all` 112 s, bước affinity
  195 s, fix50sp2 99 s, socket corpus under contention 12 s; `semver` — cài `cargo-semver-checks`
  từ source mất 296 s trên 359 s; không job nào có cache build.

## Cách làm

### 1. PR chỉ sửa tài liệu: workflow `docs.yml` riêng, `ci.yml` có bộ lọc `paths`

- Tạo `.github/workflows/docs.yml`, chạy trên mọi `pull_request` và push lên `main`, **không lọc**.
  Có một job, id `book` (giữ id vì `CONTRIBUTING.md` và ADR-0206 gọi tên nó), gồm nguyên các bước
  của ba job cũ `links`, `book`, `stranger-git`, comment mang theo. Checkout `fetch-depth: 0` (sâu
  nhất trong ba job cần). Thêm bước `scripts/check-ci-paths-filter.sh` (mới).
- `ci.yml` có cùng một danh sách `paths` ở cả `push` và `pull_request`:
  `'**'`, `'!docs/**'`, `'!*.md'`, `'!book.toml'`, rồi đưa lại `'docs/CONFIGURATION.md'`,
  `'docs/reference/prior-art.md'`.
- **"Tài liệu" nghĩa là**: mọi thứ trong `docs/`, file `*.md` ở **gốc** repo (`*` không khớp `/`),
  và `book.toml` — **trừ** các file mà test code đọc lúc chạy (hai file trên). Mọi thứ khác là
  code: `crates/**` (kể cả `README.md` của crate), `scripts/`, `benches/`, `examples/`, `tools/`,
  `fuzz/`, `spikes/`, `NOTICE`, `LICENSE-*`, `Cargo.*`, `deny.toml`, `rust-toolchain.toml`,
  `.github/`.
- `scripts/check-ci-paths-filter.sh` giữ danh sách này khớp với code: mọi đường dẫn `docs/…` hoặc
  `*.md` ở gốc mà một file trong `crates/ tools/ examples/ benches/ fuzz/ spikes/` đọc (chuỗi
  `../../docs/…`, `include_str!` ra ngoài crate) phải có dòng đưa-lại trong `paths`; và danh sách
  của `push` với `pull_request` phải giống hệt nhau. Chỉ đọc text, không cần cargo.
- **Vì sao chọn `paths` chứ không phải job `changes`** (như `dorny/paths-filter`): job phân loại
  bị tính trọn 1 phút mỗi run — khoảng 600 phút/tháng, 30 % hạn mức — cho một câu hỏi GitHub trả
  lời trước khi bật runner. Bẫy "Pending mãi" chỉ cắn khi có check bắt buộc; hôm nay không có, và
  sau khi private trên Free thì không thể có. ADR-0214 ghi rõ: nếu sau này cần check bắt buộc thì
  chỉ đặt lên job của `docs.yml`, hoặc thay ADR.

### 2. Hai tầng trong `ci.yml`

- `pull_request.types: [opened, synchronize, reopened, labeled]`; thêm `workflow_dispatch:`.
- **Tầng nhanh** (mọi push vào PR): `gates`, `no-default-features`, `lint-config`,
  `indexing-debt`, `dict-no-vendor`. Mỗi job mang `if: ${{ !(NOOP) }}`.
- **Tầng đầy đủ** (push lên `main`, chạy tay, hoặc PR có nhãn `full-ci`): thêm `bench`, `semver`,
  `feature-sets`, `deny`, `interop`, `interop-qfj`, `tls`, `no-kernel-sleep`, `standard-blocks`,
  `package`, `fixp-spike`. Mỗi job mang
  `if: ${{ (github.event_name != 'pull_request' || contains(github.event.pull_request.labels.*.name, 'full-ci')) && !(NOOP) }}`.
- `NOOP` = `github.event.action == 'labeled' && github.event.label.name != 'full-ci'`: gắn nhãn
  khác (ví dụ `documentation`) tạo một run mà mọi job đều bị bỏ qua — không job nào nhận runner.
- **Concurrency**: nhóm đổi thành
  `${{ github.workflow }}-${{ github.head_ref || github.ref_name }}${{ (github.event.action == 'labeled' && github.event.label.name != 'full-ci') && format('-noop-{0}', github.run_id) || '' }}`.
  `ref_name` làm run chạy tay trên nhánh rơi vào cùng nhóm với PR của nhánh đó (run sau huỷ run
  trước, không tính tiền hai lần). Đuôi `-noop-<run_id>` giữ cho run của nhãn lạc **không huỷ**
  run thật đang chạy.
- **Nhãn dùng một lần** (anh chọn, 2026-09-28): job cuối `drop-full-ci-label` gỡ `full-ci` sau
  run tầng đầy đủ mà nhãn gây ra, nên các lần push sau chỉ chạy tầng nhanh.
  - `needs:` cả 16 job của `ci.yml`;
    `if: ${{ !cancelled() && github.event_name == 'pull_request' && contains(github.event.pull_request.labels.*.name, 'full-ci') && !(NOOP) }}`
    — chạy dù các gate xanh hay đỏ (run đỏ mà giữ nhãn thì mỗi lần push sửa tốn 58 phút; muốn chạy
    lại tầng đầy đủ thì gắn lại nhãn).
  - Điều kiện là "run PR nào đã chạy tầng đầy đủ", không riêng run `labeled`: nếu một lần push huỷ
    run `labeled` giữa chừng thì run `synchronize` sau đó vẫn thấy nhãn, chạy tầng đầy đủ và gỡ nhãn
    ở cuối. Chỉ gỡ ở run `labeled` thì trường hợp này để nhãn nằm lại mãi.
  - **Quyền tối thiểu**: `permissions: { pull-requests: write }` chỉ ở job này; workflow vẫn
    `contents: read`. Không checkout, không action bên thứ ba (không có gì phải ghim SHA): một bước
    `gh api -X DELETE repos/${{ github.repository }}/issues/${{ github.event.pull_request.number }}/labels/full-ci`
    với `GH_TOKEN: ${{ github.token }}`, `timeout-minutes: 2`. Trả 404 (nhãn đã bị gỡ tay) thì in
    `::notice::` và thoát 0; lỗi khác thì job đỏ.
  - **Bẫy `unlabeled`**: việc gỡ nhãn phát sự kiện `unlabeled`. Hai lớp chặn: `ci.yml` không khai
    `unlabeled` trong `types`, `docs.yml` dùng `types` mặc định; và sự kiện do `GITHUB_TOKEN` gây ra
    không tạo run mới. Kết quả mong đợi: không run nào, 0 phút (R10).
  - Tốn 1 phút tính tiền mỗi run tầng đầy đủ do nhãn (không có ở run chạy tay hay trên `main`).
  - Quy trình đóng plan: **gắn `full-ci` trước khi push commit đóng** — một run duy nhất, 59 phút.
    Gắn sau khi run nhanh đã xong thì tốn 17 + 59.
- Socket corpus under contention và bộ FIXT (hàng 3 của bảng máy kiểm ở `CLAUDE.md` §2) **ở tầng
  nhanh**: cả hai là bước của `gates`, không đổi. Wiring `check-feature-gated-tests-ran.sh` không
  đổi: gọi trong `gates` (dict, codegen, fix50sp2 — tầng nhanh) và trong `tls` (tầng đầy đủ).
- `scripts/ci-evidence.sh <sha>` (mới, manager dùng, cần `gh`): tìm run `CI` và `Docs` của commit
  đó, in id và tầng, **từ chối** nếu run `CI` có job tầng đầy đủ bị bỏ qua, hoặc commit không
  phải `headSha` của run. Nó xét từng job gate, không xét kết luận chung của run, và báo riêng kết
  quả của `drop-full-ci-label` (job này đỏ không làm gate đỏ). Là thứ trả lời §9 "run xanh nào,
  cho commit nào".

### 3. Gộp job ngắn

| Gộp | Thời gian cũ | Sau | Vì sao an toàn |
|---|---|---|---|
| `links` + `book` + `stranger-git` → `book` (trong `docs.yml`) | 6 s + 17 s + 18 s = 3 phút tính | ~35 s = 1 phút | cả ba đọc tài liệu; `stranger-git` tự ghi `vendor/` không lọt được vào build của nó |
| `lint-config` + `script-logic` → `lint-config` | 43 s + 6 s = 2 phút tính | ~45 s = 1 phút | cả hai không tải `vendor/`, nên bước pin vẫn đi nhánh chỉ-sha256; `script-logic` thuần logic |

Các bước kiểm (sau bước cài đặt) trong job gộp mang `if: ${{ !cancelled() }}`: một bước đỏ không
che các bước sau, và job vẫn đỏ. Tên từng bước giữ nguyên để log vẫn đọc theo từng check.

**Không gộp**: `dict-no-vendor`, `package` (máy chưa từng thấy `vendor/`), `no-default-features`
(máy không có gì tuỳ chọn), `tls`, `interop-qfj`, `no-kernel-sleep`, `standard-blocks` (kiểm kernel
của runner trước). `indexing-debt` cũng không: gộp với `lint-config` thì vượt 60 s, không bớt phút
nào, lại đặt `vendor/` lên máy mà bước pin cần vắng `vendor/`.

`stranger-git` như vậy **chuyển từ tầng đầy đủ sang mọi PR** (kể cả PR chỉ tài liệu), không tốn
thêm phút: sửa `docs/GETTING-STARTED.md` được thử ngay với bản tag.
