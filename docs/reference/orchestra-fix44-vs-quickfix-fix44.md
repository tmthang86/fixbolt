# Orchestra's FIX 4.4 and QuickFIX's `FIX44.xml` disagree in 687 places — and three of them are traps

`[measured 2026-09-23]` `python3 scripts/dict-diff.py` at commit `4eaeb53`, on the owner's
desktop (a count, not a timing). Inputs:

| Side | File | Pin | sha256 |
|---|---|---|---|
| QuickFIX | `vendor/quickfix/spec/FIX44.xml` | `386ce46e` (`scripts/fetch-quickfix-assets.sh`) | `a82655b54363aa9c6d1b2f21f294f1198c0d7125d7b44c26d93d3179f3358425` |
| Orchestra | `vendor/orchestra/OrchestraFIX44.xml` (`version="FIX.4.4_EP311"`) | `cd24169a` (`scripts/fetch-orchestra-assets.sh`) | `a36262895e90bbcad2948e0c98072173a571a253ba63107a89617441c67a9f86` |

The program flattens both files the way `crates/dict/build.rs` does and compares nine facets
([ADR-0101](../decisions/ADR-0101-the-shipped-dictionary-is-chosen-by-a-rule-written-before-the-orchestra-diff-is-measured.md)
decision 1). It proved itself first: QuickFIX against itself gives 0 rows and reproduces
912 / 93 / 12 524 / 1 708 / 731 / 30 / 16; a planted two-row mutation is found as exactly two
rows. The full row-by-row table is regenerated by the command into `target/dict-diff/report.md`
(not committed — it is 718 lines and the command is the source of truth).

**Consequence:** outcome C of ADR-0101; the owner chose to ship QuickFIX's XML with a `NOTICE`
([ADR-0104](../decisions/ADR-0104-the-published-dictionary-is-quickfixs-xml-shipped-with-a-notice.md)).
This page stays because anyone who later proposes "just switch to Orchestra" — or to any
FIX-Repository-derived dictionary — walks into the same three traps.

The G rows are the same three members as the P rows: Orchestra's group is QuickFIX's plus one
member, inserted mid-sequence, so every member after it moves one position. The Orchestra
specification says file order is not guaranteed to be wire order
(<https://github.com/FIXTradingCommunity/fix-orchestra-spec>, `v1-0-STANDARD/orchestra_spec.md`),
so an equal *set* would not have been enough — sequence equality is what non-negotiable 5 needs.

## Trap 1 — Orchestra is an enum **superset**, so swapping to it silently widens what the engine accepts, and one field of it is in the corpus

Every one of the 663 E rows is a value Orchestra has and QuickFIX lacks; none goes the other way.
660 of them are **29 fields QuickFIX declares with no enum list at all**, which Orchestra points at a
code set — `BenchmarkCurveName(221)`, `UnderlyingSecurityIDSource(305)`, the party sub-ID types and
others. The remaining three are single values added to lists QuickFIX has: `ExecInst(18)='T'`,
`OrdStatus(39)='5'`, `OrdRejReason(103)='12'`.

Why it bites: a field with **no** list accepts any value; the same field **with** a list refuses
everything else with `Reject 373=5`. So the "superset" is a *narrowing* for the 29 fields and a
*widening* for the other three — both directions of behaviour change from one diff that reads
as "Orchestra has more". **93 of the 94 gate-visible E rows are one field, `RefMsgType(372)`**,
which QuickFIX types as a free `STRING` and Orchestra ties to the `MsgType` code set; the
acceptance corpus sends it in session-level `Reject`s.

The unit matters too: per (tag, value) pair — the rule's unit — this facet is 663 rows; per
field it is 32. ADR-0101 *Result* records why the rule's unit was kept.

**Guarded by:** `crates/dict/tests/enums.rs`
`the_table_matches_the_xml_field_for_field_and_value_for_value`, which compares the generated
table with the shipped XML value for value in both directions; and
`a_field_without_an_enum_answers_none_rather_than_yes`, which pins the "no list" meaning.

## Trap 2 — "required" lives on a different node: QuickFIX wraps a group in a component, Orchestra marks the group itself

In QuickFIX's `FIX44.xml`, `Parties` is a `<component>` whose only child is
`<group name='NoPartyIDs' required='N'>`; a message references the component, sometimes with
`required='Y'`. `build.rs` does not let a required component make its members required
(`crates/dict/tests/tables.rs` `a_required_component_does_not_make_its_fields_required`), so
`NoPartyIDs` stays optional. Orchestra has no wrapper: `Parties` is a `<fixr:group>` reached by a
`groupRef` carrying `presence="required"` directly. Same intent, different node — and a reader
that ports QuickFIX's rule faithfully turns 14 optional groups into required ones (`35=AK`–`AW`,
the position and confirmation messages). Only `CollInquiryID(909)` on `35=BB` is a genuine
disagreement.

Why it bites: a required group that is absent is `Reject 373=1`. Five message types would start
refusing messages QuickFIX accepts, and no `.def` sends any of them, so the 59 would stay green.

**Guarded by:** `crates/dict/tests/tables.rs`
`a_required_component_does_not_make_its_fields_required` and
`required_descends_into_required_components` (the rule on the QuickFIX shape); any future
Orchestra reader needs its own test that a `groupRef presence="required"` and a required wrapper
component produce the **same** answer.

## Trap 3 — tag 327 has a different **name**, and names become public constants

QuickFIX calls tag 327 `HaltReasonChar`; Orchestra (and the FIX Repository) call it
`HaltReason`. `build.rs` emits tag constants from names (`screaming(name)`), so a source swap
renames `HALT_REASON_CHAR` to `HALT_REASON` — a **public API break** in `fixbolt-dict` that no
tag number, pair or enum comparison notices, because the number is unchanged. After `0.1.0` it is
a `cargo-semver-checks` failure; before it, it is silent.

**Guarded by:** `crates/dict/tests/interop_quickfix_fields.rs`, which walks every FIX 4.4 name
and requires the number QuickFIX's `FixFieldNumbers.h` gives it — that header knows 327 only
as `HaltReasonChar` and `HaltReasonInt`, so a table carrying `HaltReason` fails the walk
(checked 2026-09-23 by grep at pin `386ce46e`); and, after the first publish, `cargo semver-checks` (ADR-0097 exit
criterion 8).

## Smaller things the scouting saw

- 68 Orchestra elements carry `updated="FIX.Latest"`: later errata applied back to the "frozen"
  4.4 file (ten commits since 2023). A pin is the only thing that keeps the file still.
- One attribute reads `deprecated="FIIX.4.4"`. A reader that trusts attribute values it does not
  need will one day trust a typo.
- Orchestra puts the real datatype on the code set (`type="…CodeSet"` on the field), so a type
  comparison that does not resolve the indirection reports every enumerated field as different.
